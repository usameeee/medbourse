# Changelog

All notable changes to MEDBOURSE are documented here with verification notes where applicable.

## [Unreleased]

### Added

- Initial repository audit (2026-10-13): confirmed greenfield workspace at `medbourse`.
- Permanent project documentation: AGENTS.md, PROJECT_CONTEXT.md, PROJECT_STATE.md, ROADMAP.md, TASKS.md, DESIGN_SYSTEM.md, ARCHITECTURE_DECISIONS.md, docs/*.
- Cursor rule adapters under `.cursor/rules/`.
- Monorepo scaffold: `apps/api`, `apps/web`, `packages/shared`.
- Git repository initialized (no commits yet).
- Web design tokens (`apps/web/src/styles/tokens.css`) aligned with DESIGN_SYSTEM.md.
- API error handler, Zod validation middleware, shared `ROLE_PERMISSIONS` / `ApiErrorBody`.
- Email provider decision: Gmail SMTP + Google App Password (`docs/EMAIL.md`, ADR-008). API config reads SMTP env vars; no send implementation yet.
- MongoDB Atlas connection on API startup (mongoose). Health includes `database`. Operator probe: `npm run db:check -w @medbourse/api`.
- i18n: `react-i18next` with en/tr/fr/ar catalogs, language switcher, `html` `lang`/`dir` (RTL for Arabic). `useSuspense: false` so the shell renders without a Suspense boundary.
- Auth skeleton: User model, bcrypt, HTTP-only JWT cookie `mb_access`, Bearer fallback, register/login/logout/me, RBAC `requirePermission`. Public register is always `customer`. Account panel on the web shell.
- Customer records independent of User. Staff can create customers without accounts; duplicate emails return 409; linked users may read only their own customer.
- Country assignment maps (primary manager first). Unmapped → `unassigned`; inactive mapped manager → `exception`. Map changes do not rewrite assigned customers. Admin reassignment requires a reason and writes `AuditLog`. Express 5 query validation uses defineProperty.
- Secure invitations: SHA-256 token, 7-day expiry, revoke, email must match. Register without token does not claim a customer. SMTP send still Phase 7.
- Catalog: cities and providers. Super Admin writes; public GET is active-only. `partnershipVerified` defaults to false.
- Offerings (program / medical / tourism) on providers. Server-set category disclaimer; guarantee language rejected (`GUARANTEE_LANGUAGE`).
- Pricing rules + immutable quotations. Money via `decimal.js` (2 dp string + ISO currency). Precedence offering 4 + category 2 + country 1; ties → `AMBIGUOUS_PRICING`.
- Payment accounts (IBAN/SWIFT) configured by Super Admin. Resolved live by quotation currency + customer country. No bank details in source. Audit stores IBAN tail only.
- Cases: staff opens an application for a customer + offering; optional quotation must match; customers read only their own cases.
- Private case documents (PDF/JPEG/PNG/WebP, 10MB). Signed 60s URLs. Cloudinary private upload when `STORAGE_DRIVER=cloudinary`; tests use in-memory storage.
- Payment evidence: receipt upload is `submitted` until staff `payment:verify:staff` review. Quotation snapshots are not marked paid.
- Workflow templates (P5-T01): Super Admin creates versioned stage graphs per service category. A new case snapshots the active template's current version; later template edits do not affect in-flight cases. New permission `workflow:manage:super_admin`. Routes under `/workflow-templates` (CRUD + `/versions`). Case response includes `workflow` snapshot (each stage starts `pending`).
- Workflow stage transitions (P5-T02): Staff advance case stages via `PATCH /cases/:id/workflow/stages/:stageId` with `{ status }`. Allowed: `pending → in_progress|done|skipped`, `in_progress → done|skipped`. Completing a stage requires all earlier non-optional stages to be `done` (409 `PREREQUISITE_NOT_DONE`). Only optional stages may be skipped (400 `STAGE_NOT_OPTIONAL`). Every transition writes `case.workflow_stage_transitioned` to `AuditLog`. New permission `case:workflow:staff`.
- Case close (P5-T03): Staff close a case with `PATCH /cases/:id/close`. Requires all non-optional workflow stages to be `done` (409 `REQUIRED_STAGES_NOT_DONE`); already-closed cases return 409 `CASE_ALREADY_CLOSED`; customers get 403. Closing writes `case.closed` to `AuditLog`. The case timeline (snapshot stages + statuses) is readable via `GET /cases/:id` for staff and the linked customer.
- Staff/Admin case list with filters and pagination (P6-T01): `GET /cases` is country/assignment scoped for staff and admin (super_admin sees all). Staff see only cases whose customers belong to a country they manage via `CountryAssignment` or where they are the directly assigned manager. Filters: `status` (open|closed), `category` (education|medical|tourism), `customerId`. Pagination via `page`/`limit` (max 100); sorted by `createdAt` descending. `customerId` outside scope returns empty; invalid values return 400. Single-case reads (`GET /cases/:id`) and document access are now country-scoped for consistency. New `caseAccess` helpers: `getAccessibleCustomerScope`, async `canReadCase`, async `canManageCaseDocuments`.
- Staff case detail view (P6-T02): `GET /cases/:id` now returns `documents` (case documents sorted by createdAt desc), `quotation` (the linked quotation or `null`), and `paymentEvidence` (list of receipt evidence for the quotation). Country-scoped access is enforced. No quotation → `quotation: null` and `paymentEvidence: []`.
- Super Admin audit log viewer (P6-T03): `GET /audit` lists `AuditLog` entries for `super_admin` only (`audit:read:super_admin`). Filters: `action`, `entityType`, `actorUserId`. Pagination via `page`/`limit` (max 100); sorted by `createdAt` desc (with `_id` desc tiebreaker). Invalid `actorUserId` or out-of-range `limit` returns 400; non-super-admin roles return 403.
- Staff workspace portal shell + case list (P6-T04a): First operational frontend surface. `PortalShell` provides a role-aware header (brand, user, logout, language switcher) and tab navigation (`cases` for all roles; `customers` for staff+; `catalog` and `audit` for super_admin only). `CasesView` renders a scannable table with `status` and `category` filters, pagination, and `Intl`-formatted dates, backed by a new typed API client (`listCases`, `getCase`, `listCustomers`, `listOfferings`) with cookie auth. `StatusBadge` maps case/workflow/payment/category enums to semantic colors. All UI strings localized in en/tr/fr/ar. Unauthenticated users see the existing health + sign-in panel.
- Case detail view (P6-T04b): Clicking a row in `CasesView` opens `CaseDetailView`, which renders the case header (title, category + status badges, creation date), the versioned workflow timeline (stage name, status dot, description, optional tag), the documents list (kind label, size), and the quotation block (currency-formatted amount, offering/category/issued-at, disclaimer) plus payment evidence list (status badge, review note). Back button returns to the case list. Country-scoped access is enforced server-side by `GET /cases/:id`. All strings localized in en/tr/fr/ar.
- Catalog admin surface (P6-T04c): Super Admin can manage cities, providers, and offerings from the portal. New `CatalogView` with tabbed sections (cities/providers/offerings), inline create/edit forms, active-state pills, and reference selects (provider → city, offering → provider). Typed API client extended with `listCities`/`createCity`/`updateCity`, `listProviders`/`createProvider`/`updateProvider`, and `createOffering`/`updateOffering`; `listOfferings` now takes `ServiceCategory`. `App` renders `CatalogView` on the catalog tab (super_admin only). Existing RBAC catalog endpoints and audit writes are reused unchanged. All strings localized in en/tr/fr/ar.
- Development seed (`npm run db:seed -w @medbourse/api`): idempotent upsert of demo accounts (`root@medbourse.dev` super_admin, `staff@medbourse.dev` staff) plus catalog data (2 cities, 2 providers, 2 offerings, 1 customer). Never deletes records; the shared password is overridable via `SEED_PASSWORD`. Fills the gap where staff/admin/super_admin accounts had no creation path (public register always creates a `customer`; invitations only link customers).
- Case-linked messaging (P7-T01): New `Message` model (caseId, authorUserId, authorRole, body, createdAt) with a `{ caseId, createdAt }` index, and `GET`/`POST /cases/:id/messages` under the new `case:message:self` permission. Both endpoints reuse `canReadCase`, so the linked customer and in-country/assigned staff can read and post while strangers and out-of-scope staff get 403 (unauthenticated 401; unknown case 404; blank body 400). Each create writes a `case.message_created` `AuditLog` entry. The portal `CaseDetailView` gains a `MessageThread` (chronological list with author role, timestamp, own-message highlight, and a composer); the typed client adds `listCaseMessages`/`createCaseMessage`. All strings localized in en/tr/fr/ar.
- In-app notifications (P7-T02): New `Notification` model (recipientUserId, type, caseId, metadata, readAt, createdAt) with recipient/read indexes, plus a `notification:read:self` permission on every role. `GET /notifications` returns only the caller's rows (newest first, optional `unreadOnly`, pagination) with an `unread` count in `meta`; `PATCH /notifications/:id/read` marks one and `POST /notifications/read-all` marks all — another user's row returns 404. A `notifyCaseEvent` service resolves recipients (linked customer user for customer-facing events; case creator + assigned manager for staff-facing events) and never notifies the actor; it is emitted from message creation, workflow stage transitions, case close, and payment-evidence submit/review. The portal `PortalShell` gains a `NotificationBell` (unread badge, dropdown list with per-type localized labels, mark-read and mark-all). All strings localized in en/tr/fr/ar.
- Email dev mode documented (P7-T03): `docs/EMAIL.md` is now the authoritative contract — outbound mail is **not sent**, the API records intent only via `recordOutboundMail(kind, to)` (log line `mail deferred (<kind>) to=<address> — dev mode: not sent`); `SMTP_*` config is read but unused; call sites are customer invitations (token returned once, never emailed/logged) and in-app notifications (stored, not emailed). It documents the non-negotiable safety rules (never log `SMTP_PASS`/tokens/PII; never claim delivery) and the Gmail App Password setup for the future send path. `devMail.ts` comment/log and cross-references (`.env.example`, `docs/API.md`, ADR-008, ADR-011) were aligned. No real send path is implemented. Phase 7 complete.
- Customers admin surface (P8-T01): New `CustomersView` replaces the `customers` tab placeholder in `App.tsx`. It lists customer records (`GET /customers`) with a `q` search over name/email, prev/next pagination, and columns for name, email, phone, country, assignment-status pill, and created date; a create form issues `POST /customers` (name, optional email/phone, ISO-2 country). Per-row **Invite** calls `POST /customers/:id/invitations` and renders the returned one-time `token` (plus email and expiry) in a dismissible panel that is never persisted client-side; records without an email show an inline email prompt. Only wired RBAC endpoints — no fake actions. Typed client adds `createCustomer`/`inviteCustomer`; `PublicInvitation` added to `@medbourse/shared` and `toPublicInvitation` now returns it. All strings localized in en/tr/fr/ar with logical CSS (RTL-safe).
- Customer reassignment (P8-T02): New admin-only `GET /users/managers` returns active assignable managers (staff/admin/super_admin) via `listAssignableManagers`, excluding customers/inactive accounts and never exposing `passwordHash`. `CustomersView` gains an admin-gated (`assignment:manage:admin`) per-row **Reassign** action that opens a panel (manager select + reason) calling the existing `POST /customers/:id/assignment` and reloading the row; the control is hidden for staff/customer callers and when the directory fails to load (no fake action). Typed client adds `listManagers`/`reassignCustomer`. New `apps/api/src/users.test.ts` covers access control + filtering; all strings localized in en/tr/fr/ar with logical CSS (RTL-safe).
- Public marketing site (P8-T03): New `PublicSite` component replaces the minimal unauthenticated shell in `App.tsx`. It renders a top bar (brand + anchor nav + language switcher), a hero, a three-line services section (education/medical/tourism, localized copy), and an offerings section fed by the public catalog endpoints (`listOfferings`/`listProviders`/`listCities`) showing each active offering's category badge, summary, requirements, provider + city, and the server-set disclaimer — with loading/error/empty states. A contact/account block precedes the existing `AuthPanel`, and the system-status panel moves into a footer. No fabricated metrics, partners, or contact details; only real, wired data and actions. All strings localized in en/tr/fr/ar with logical CSS (RTL-safe); the authenticated portal is unchanged.
- Critical end-to-end journey (P9-T01): New `apps/api/src/qa.journey.test.ts` drives the whole master-spec golden path through the real API in a single test — catalog → pricing rule → payment account → workflow template → country assignment → customer + invitation → self-registration (account linked) → quotation (frozen snapshot survives a later offering rename) → case (workflow version snapshot, all stages `pending`) → document upload → payment instructions (full IBAN to the owner) → receipt upload (`submitted`, not auto-approved) → messaging (staff notified, actor excluded) → premature close 409 `REQUIRED_STAGES_NOT_DONE` → out-of-order stage 409 `PREREQUISITE_NOT_DONE` → stages advanced → optional stage skipped → receipt approved (re-review 409 `ALREADY_REVIEWED`) → close → customer final view → audit trail with `case.created`/`case.workflow_stage_transitioned`/`case.closed`. No production code changed.
- Security & authorization matrix (P9-T02): New `apps/api/src/qa.security.test.ts` (9 tests) covering the `docs/SECURITY.md` threat model — anonymous → 401 across 12 protected endpoints (public catalog stays 200); role matrix (customer/staff/admin) → 403 per `ROLE_PERMISSIONS`; cross-customer IDOR blocked on case/documents/messages/quotation/payment-instructions/receipt signed-url (403) and foreign notifications (404), with an own-case positive control; public `register` cannot choose a privileged role; audit stores only the IBAN tail; 403 bodies leak no stack traces. No production code changed.
- OpenAPI specification (P10-T01): New `docs/openapi.yaml` (OpenAPI 3.1.0) documents the whole `/api/v1` surface — **47 paths / 61 operations / 97 schemas** across 16 tags. Dual security schemes `cookieAuth` (apiKey/cookie `mb_access`) and `bearerAuth` (JWT), with public endpoints (`GET /health`, `POST /auth/logout`, public catalog reads, signed content routes) set to `security: []`. Schemas mirror `@medbourse/shared` `Public*` types; request bodies carry the real Zod constraints; error responses use the specific `AppError` codes. Verified against the code (no missing, no invented operations) and parses cleanly. `docs/API.md` now points at the spec as the machine-readable source of truth.
- Deployment guide (P10-T02): New `docs/DEPLOYMENT.md` — topology, prerequisites (Node ≥20), the full environment-variable table (incl. `JWT_SECRET` signing both sessions and signed URLs, and the build-time `VITE_API_BASE_URL` caveat), API (`npm run start -w @medbourse/api`) and web (static `apps/web/dist`) build/run, MongoDB Atlas connectivity (`db:check`) and the idempotent seed, the storage-driver matrix (`memory`/`local`/`cloudinary` with the 60s signed-URL and `400 SIGNED_URL_ONLY` behavior), CORS/cookie/HTTPS guidance (`SameSite=Lax` ⇒ serve web + API on the same registrable domain), and a post-deploy smoke test. Placeholders only — no secrets.
- Operations & backup notes (P10-T03): New `docs/OPERATIONS.md` — what to back up, MongoDB Atlas cloud/on-demand backup + restore + PITR, local `.data/private-docs` backup (row↔file coherence; single-instance constraint for the `local` driver), logs/monitoring with alert signals (health, `500` bursts, auth `401`/`429`), the append-only audit-trail policy, routine secret rotation (rotating `JWT_SECRET` invalidates sessions + signed URLs), and first-response incident steps.
